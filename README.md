# PaperTrail｜任务导向的文献阅读 Agent

**面试展示版本 v0.1** · 单文献阅读 Agent + 多 Skills + 原文证据核查 + 人工确认 + 成果卡片

> 当前交付的是**能在本地运行、可部署到云服务器的完整网页项目**。它不是已公开上线的网站：公网 URL 需要部署者登录自己的云平台完成发布。没有 `OPENAI_API_KEY` 时，系统会清楚显示「演示模式」，绝不会伪装已调用 GPT-4.1。

## 1. 运行方式（Windows）

1. 解压 `PaperTrail_文献阅读Agent.zip`。
2. 需要 **Python 3.11 或以上版本**。双击 `start_windows.bat`（首次运行需要联网安装依赖）。
3. 在浏览器打开 **http://127.0.0.1:8000**。
4. 点击「体验示例」导入一篇**原创、虚构、非正式发表**的三页测试 PDF；输入阅读目标后进行「相关性判断 → 确认精读 → 定向提取 → 查看 PDF 原文 → 人工确认保存」。
5. 在「阅读成果卡」中可浏览、导出 Markdown/JSON；在「文献库」删除论文将同时删除关联任务与卡片。

在 PowerShell / macOS / Linux 中也可手动启动：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS / Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

## 2. 如何真正启用 GPT-4.1

复制 `.env.example` 为 `.env`，编辑以下内容：

```ini
OPENAI_API_KEY=sk-你的API密钥
OPENAI_MODEL=gpt-4.1
DATA_DIR=./data
ENABLE_OCR=false
COOKIE_SECURE=false
```

保存并重启服务器。API Key **只保存在服务端**，不会通过浏览器输入框、前端 JavaScript 或响应返回给访客。前端状态显示「GPT-4.1 · 已配置」仅表示检测到密钥，**不代表已经测试 API Key 或模型权限**。

**不要将 `.env` 上传到 GitHub / 简历附件 / 公开网盘。** `.gitignore` 已排除该文件及 `data/`。

模型调用使用 OpenAI **Responses API**（`/v1/responses`），并关闭 API 的响应存储选项 `store:false`。按实际调用额度计费。上传的正文片段会传给模型服务用于生成结果；不适合处理禁止向外部模型传输的机密材料。

## 3. 功能链路与技术架构

```text
研究背景 + 阅读目标
        ↓
单篇 PDF 上传与解析（PyMuPDF / 可选 Tesseract OCR）
        ↓
正文按 PDF 页切分，保留页码、建立轻量检索片段
        ↓
阅读 Agent：相关性判断 Skill（先反馈用户）
        ↓ 用户确认精读
定向 Skills：指标提取 / 方法分析 / 结论与局限
        ↓
原文检索工具：双语词与中文 2-gram 轻量排序
        ↓
两层核验：① 字符串确实见于原文 ② GPT 语义支持核验
        ↓ 用户编辑与显式确认
SQLite 持久化阅读卡片 → 原文定位 → Markdown / JSON 导出
```

- **Agent**：一个阅读任务只由一个阅读 Agent 控制，任务规则由 `skills.py` 定义；流程和检索工具在 `engine.py` 编排，避免无必要的多 Agent 复杂度。
- **Skills**：不仅有一句 Prompt，另有目标、输入问题、边界规则、字段与检索关键词，便于检验和版本迭代。
- **检索**：当前为基于页面切块的轻量本地检索，**不是外部向量数据库**；短论文通常全部进入候选片段，长论文按关键词召回。复杂表格、双栏和扫描件需要更多人工验证。
- **核查**：引文先验证在指定 chunk 中逐字出现（忽略排版空白差异），再通过模型进行单独语义支持核查。未通过或核验调用失败的条目标记「待核查」。模型支持核验不等于学术事实已经被证明。
- **人机协作**：用户必须明确确认相关性和阅读卡片；结论和笔记在保存前可编辑，证据引文被保留供核验。
- **成果存储**：SQLite 保存每个匿名会话下的论文、阅读任务、卡片以及最小化事件统计；原始 PDF 保存在服务器文件目录，用户可删除。

## 4. 演示模式是什么？

如果没有 API Key，仍能实际完成以下流程：

- PDF 上传、解析、页码检测和片段索引；
- 依据关键词估算任务相关线索，输出真实的原文位置；
- 利用可检查的**本地正则规则**在演示论文中识别「指标一、指标二、指标三」等段落，生成可编辑的**原文线索草稿**；
- 原文 PDF 打开、人工确认、卡片保存、删除与导出。

它**不能**代替 GPT-4.1 的语义阅读、研究方法理解、事实核验，因此界面中明确标识「演示模式」「待核查」。所有演示论文中的城市研究数据都是虚构文本，不可作为真实学术来源。

## 5. 部署成简历可填的网页链接

该项目是单服务 FastAPI：后端负责 API 和静态页面，避免前后端分开部署。

推荐流程（例如 Render）：

1. 将解压后的项目推送到**你自己的 GitHub 仓库**（务必排除 `.env`、`data/`）。
2. 在 Render 通过仓库创建 Web Service 或 Blueprint，`render.yaml` 已提供 Python 服务设置。
3. 环境变量中设置 `OPENAI_API_KEY`、`OPENAI_MODEL=gpt-4.1`、`COOKIE_SECURE=true` 和 `DATA_DIR=/var/data`。
4. 如果需要**长期保留**上传的论文和卡片，配置挂载到 `/var/data` 的持久磁盘。`render.yaml` 使用磁盘配置，**可能需要付费方案**。如果用不带磁盘的免费/临时文件服务，实例重建后数据可能丢失，不能承诺成果永久保存。
5. 部署成功后平台才会生成 `https://你的项目域名/` 的**真实可公开访问 URL**。当前项目压缩包**本身不等于公网链接**。
6. 面试时建议首先上传不含隐私的演示论文，保留一张真实复核过的样例成果卡，再用浏览器操作展示。

**安全提醒：**该版本是求职演示 MVP，不是支持真实多用户的正式 SaaS。它使用随机匿名 Cookie 隔离数据，未提供账号系统、复杂权限、公开站点速率限制或组织级审计。公开启用付费模型之前务必增加身份校验、配额限制和异常告警，避免陌生人消耗 API 额度。只上传有权处理的论文材料。

## 8. 面试时怎么介绍（可据真实验证更新）

“我在研究生阶段读文献时发现，普通 AI 总结工具很难围绕具体研究任务稳定提取信息，生成的结论也不一定能直接追溯到原文。因此我设计了一个单文献阅读 Agent，先解析并定位 PDF 原文，再根据研究目标判断相关性，按指标提取、研究方法分析等 Skills 定向处理。为了避免 AI 生成无依据的说法，我设计了引文存在性校验和语义支持核验两层机制，并在相关性确认和最终卡片保存之前保留人工决策。开发上我把产品需求、异常和验收标准拆给 Codex 协作实现，重点负责工作流、Skill 规则、质量标准和测试。”
